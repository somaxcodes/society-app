## UI/UX Design and Frontend Polish – High Priority

I want to improve the frontend of our existing application using Pico.css and custom CSS.

I want the application to look polished, thoughtfully designed and professional. I specifically want to avoid the generic AI-generated appearance that many applications have, such as excessive gradients, unnecessary animations, generic card layouts, random colours and decorative elements that serve no purpose.

### 1. Target audience and accessibility

One of my main considerations is that elderly people, including people who are not particularly comfortable with technology, should be able to use this application independently.

Design the interface with simplicity and accessibility as priorities.

Consider the following:

- Use sufficiently large, readable text.
- Maintain good colour contrast.
- Make buttons large enough to click or tap comfortably.
- Use clear, descriptive button labels instead of ambiguous icons.
- Avoid unnecessary technical terminology.
- Keep navigation predictable and consistent.
- Make the most important actions immediately visible.
- Provide clear instructions wherever users might be confused.
- Avoid cluttering the interface with too many options.
- Make forms straightforward, with clearly labelled fields and helpful validation messages.
- Make errors understandable to ordinary users and explain how they can resolve them.
- Ensure the application works comfortably on mobile screens.

The interface should not make elderly users feel that they need someone else's help to operate it.

### 2. Visual design direction

I want a clean, modern and professional design with a consistent visual identity.

Please:
- Continue using Pico.css as the foundation.
- Use custom CSS to improve the visual appearance.
- Establish a consistent colour palette, typography, spacing system and button styles.
- Use visual hierarchy to distinguish headings, instructions, primary actions and secondary information.
- Use whitespace effectively.
- Keep the layout clean without making it look empty or unfinished.
- Use icons only when they genuinely improve understanding.
- Avoid unnecessary gradients, glassmorphism, excessive shadows and decorative animations.
- Avoid making every section look like a separate card.

The final result should feel like a thoughtfully designed real-world product, not a generic AI-generated dashboard.

### 3. User experience and application states

I want every important interaction to provide clear feedback.

Implement appropriate:

- Loading states: Users should know when something is processing.
- Empty states: Explain what the user is seeing and what action they can take next.
- Error states: Explain what went wrong in simple language and provide a recovery action wherever possible.
- Success states: Clearly confirm when an action has been completed.
- Form validation: Identify missing or incorrect information near the relevant field.

Avoid situations where users click a button and have no idea whether anything happened.

### 4. Mobile responsiveness

The application must work on both desktop and mobile.

Check:
- Text readability on smaller screens.
- Button sizes and spacing.
- Navigation behaviour.
- Form layouts.
- Tables or other content that might overflow.
- Consistent spacing across screen sizes.

Do not simply shrink the desktop layout to fit a phone. Adapt the layout where necessary.

### 5. Practical implementation constraints

We have until November 8, 2026, to complete the application. I want to spend approximately 3–4 days improving and implementing the UI alongside the core functionality.

Therefore:

- Do not introduce a new frontend framework.
- Do not rewrite working backend functionality just to improve the appearance.
- Do not introduce unnecessary dependencies.
- Prioritise changes that have a visible and meaningful impact.
- Focus on the most important user journeys first.
- Do not spend hours perfecting minor decorative details.
- Keep the code maintainable and consistent with the existing project architecture.

Before making changes, inspect the existing frontend, templates, routes and CSS.

Understand the current implementation before suggesting modifications.

### 6. Work with me, don't just design for me

I am learning how to build a complete application for the first time.

Explain:
- What changes you propose.
- Why those changes improve usability.
- How Pico.css and our custom CSS work together.
- How responsive layouts are implemented.
- How accessibility considerations affect our design decisions.
- How loading, empty, error and success states are implemented.

Show me the relevant code changes and explain the important parts.

Do not blindly replace entire files without explaining what changed.

### 7. Your design and implementation priorities

Work in this order:

1. Make the main user journey intuitive.
2. Improve readability and accessibility.
3. Establish consistent visual styling.
4. Improve forms, buttons and navigation.
5. Implement loading, empty, error and success states.
6. Make everything responsive.
7. Polish smaller visual details.

Before implementing, review the actual project and identify the three to five highest-impact UI improvements.

Do not invent features or redesign functionality that is not part of the requirements.

**Final objective:** Deliver an application that looks professional, feels thoughtfully designed, works well on mobile and can be comfortably operated by elderly users or people with limited technical experience. I want the design to be achievable within our remaining development time without compromising the application's core functionality.
